# סימולטור עולם הסוכנים

אפליקציית אינטרנט בעברית שמדמה עולם של סוכני AI עצמאיים. לכל משתמש יש עוזר אישי שמנהל שיחה עם סוכן של עסק (פיצה שמש, קופת חולים, מלון), ואתם צופים בשיחה ובתוצאה הסופית. **זו סימולציה בלבד**: אין שיחות, תשלומים או אינטגרציות אמיתיות. הסוכנים העסקיים מתנהגים כמו נציגים אנושיים ואינם יודעים שהצד השני הוא AI.

## מבנה
- `public/` – חזית (HTML/CSS/JS רגיל, ללא build). ב-Vercel מוגשת ישירות כקבצים סטטיים.
- `api/index.py` – FastAPI: `GET /api/agents`, `POST /api/step`. בפיתוח מקומי מגיש גם את `public/`.
- `api/_gemini_client.py` – כל הגישה ל-Gemini והמפתח (רק בשרת).
- `api/_prompts.py`, `api/_agents_config.py`, `api/_schemas.py` – פרומפטים, הגדרת הסוכנים וסכמות.
  הקבצים מתחילים ב-`_` כדי ש-Vercel לא יהפוך אותם לפונקציות נפרדות. `index.py` מוסיף את תיקיית `api` ל-`sys.path`, ו-`vercel.json` מצרף אותם לפונקציה דרך `includeFiles`.

## משתני סביבה
| משתנה | חובה | תיאור |
|---|---|---|
| `GEMINI_API_KEY` | כן | מפתח מ-Google AI Studio (Free Tier מספיק) |
| `GEMINI_MODEL` | לא | ברירת מחדל `gemini-2.5-flash` (ניחוש סביר, לא אומת מול המפתח שלכם) |

לעולם אל תכניסו מפתח לקוד או ל-Git. `.env` מוחרג ב-`.gitignore`.

## בחירת מודל
שם המודל לא נעול. כדי לראות אילו מודלים זמינים למפתח שלכם:
```
python api/_gemini_client.py
```
בחרו מודל Flash מהרשימה והגדירו אותו ב-`GEMINI_MODEL` (בלי לשנות קוד).

## הרצה מקומית
```
python -m venv .venv && source .venv/bin/activate   # ב-Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env     # ערכו את GEMINI_API_KEY
uvicorn api.index:app --reload
```
פתחו http://127.0.0.1:8000

## פריסה ל-Vercel
1. דחפו את הפרויקט ל-Git (בלי `.env`) וייבאו אותו ב-Vercel, או הריצו `vercel`.
2. ב-Settings → Environment Variables הוסיפו `GEMINI_API_KEY` (ואופציונלית `GEMINI_MODEL`).
3. בצעו Deploy. `public/` מוגשת כאתר סטטי, `/api/*` מנותב ל-FastAPI ב-`api/index.py` (האובייקט `app`), וקבצי `api/_*.py` מצורפים לפונקציה.
4. אחרי הפריסה בדקו ש-`/api/agents` מחזיר רשימה, שהדף הראשי נטען, ושבקשה לדוגמה רצה. אם גרסת הפייתון ב-Vercel אינה מתאימה, הוסיפו קובץ `.python-version`.

**הערה:** הפריסה לא נבדקה בפועל בסביבת Vercel בזמן הכתיבה. יש לאמת אותה אחרי הפריסה הראשונה.

## מגבלת קצב (Free Tier)
כשמתקבלת שגיאת 429, הלקוח מציג הסבר וטיימר ספירה לאחור (30 שניות או הערך מ-Gemini) וחוזר על אותו צעד אוטומטית, עד 5 ניסיונות לצעד. אחר כך מופיע כפתור "נסה שוב" והתמלול נשמר. כפתור "ביטול" עוצר את הריצה. ריצה שהופסקה אפשר להמשיך גם אחרי פתיחתה מההיסטוריה; אם הייתה שאלה פתוחה למשתמש, היא תוצג שוב. כפתור "נסה שוב" לא מוצג בשגיאות שאין טעם לנסות שוב (למשל נתונים לא תקינים).

## איך זה עובד
השרת חסר מצב: בכל קריאה ל-`/api/step` הלקוח שולח את התמלול והפרופיל, והשרת מחזיר הודעה אחת. העוזר מחזיר JSON עם `status` מסוג Enum (`continue`, `need_user_info`, `done`, `failed`), כדי שהקוד יוכל להחליט מה לעשות בלי לנחש מטקסט חופשי. הסוכנים העסקיים מחזירים טקסט חופשי. עד 10 תורות עוזר מול העסק לריצה (שאלות למשתמש אינן נספרות), והשרת אוכף את אותה תקרה; בהגעה אליה הלקוח מציג כרטיס כישלון. ההיסטוריה (עד 50 ריצות) והפרופיל נשמרים ב-localStorage.

## הוספת סוכן
הוסיפו רשומה ל-`AGENTS` ב-`api/_agents_config.py` (id, name, type, emoji, description, persona, rules, knowledge). אין צורך בשינויים נוספים.

## רשימת בדיקות ידנית
- הזמנה מלאה: "תזמין לי שלוש פיצות מפיצה שמש" עם פרופיל מלא, ובסוף כרטיס תוצאה.
- מידע חסר: פרופיל ריק, ובדיקה שמופיעה שאלה למשתמש והשיחה ממשיכה אחרי התשובה.
- סוכן לא מוכר או בקשה מחוץ להיקף ("תזמין לי טיסה"): כרטיס כישלון עם הסבר.
- שגיאת Gemini (מפתח שגוי): הודעת שגיאה וכפתור "נסה שוב".
- מגבלת קצב: ספירה לאחור, המשך אוטומטי, ואחרי 5 ניסיונות כפתור ידני.
- תקרת סבבים: כרטיס כישלון אחרי 10 תורות עוזר.
- ביטול באמצע, פתיחת ריצה מההיסטוריה (כולל כזו עם שאלה פתוחה) ושליחת בקשה חדשה בזמן ריצה (נחסמת).

## אבטחה
המפתח נקרא רק ב-`api/_gemini_client.py` ממשתנה סביבה, נשלח ל-Gemini בכותרת, ואינו נרשם ביומנים או מוחזר ללקוח. הודעות שגיאה מנוקות ממנו. הפרומפטים מורים לשני הצדדים להתייחס לדברי הצד השני כשיחה ולא כהוראות.
